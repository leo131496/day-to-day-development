# 序 · 项目工作台

轻量的多项目管理应用：从项目内容生成工作清单，统一维护责任分工、排期工时、进度、风险及交付验收。内置海康 × 致趣项目原有的 50 项计划；Python 标准库 + SQLite，无须安装第三方运行依赖。

## 已实现

- **多个项目**：新增、查看、编辑、删除到回收站、恢复，项目数据相互隔离。
- **任务增删改查**：自定义编号、阶段、负责人、协作方、项目内容、排期、状态、完成率、优先级、跟进日期、下一步行动、问题风险、协调决策、验收标准、交付链接和验收结论。
- **自动生成**：粘贴按行或编号整理的项目内容，提取任务、阶段、明确写出的负责人和日期，预览勾选后保存。现有项目可继续追加生成任务。
- **导入工作清单**：本地文件或文档链接 → 预览编辑 / 勾选 → 保存入库，自动更新工作清单与看板。新增和按编号更新两种方式，导入前备份、整批事务、版本冲突检查及重复保存保护。
- **项目工作清单**：进入项目默认打开按阶段分组的工作清单，展示 WBS 编号、工作事项和内容、负责人、协作人、当前状态、开始 / 结束日期、有效工作日、计划工时及进度百分比；支持搜索、阶段 / 负责人 / 状态 / 关注事项筛选和排序。
- **四个关联视图**：项目工作清单、可视化看板、状态看板、进度与工时。新增、修改和删除工作项后同步计算。
- **自动可视化看板**：交付时间线、任务总数 / 已完成数、状态分布、阶段环形图、负责人堆叠柱状图、排期甘特图、负责人执行进度和交付风险；点击图表联动筛选，点击工作项可直接编辑。支持手机浏览。
- **工作日工时**：起止日期均计入，每个有效工作日 8H；扣除中国大陆放假和周末，计入调休补班。内置 2025、2026 年国务院通知安排，支持按账号维护年度日历及跨年计算；缺少日期或年度日历时明确提示，不猜算。
- **持久保存**：SQLite 数据库事务、WAL、FULL 同步；只有事务提交成功才显示保存成功。服务重启不覆盖已有数据，种子计划仅初始化一次。
- **防误操作**：项目和任务删除均可恢复；任务每次修改、导入、归档和恢复均保留历史版本；并发编辑使用版本检查，不静默覆盖。
- **草稿保护**：填写时保留当前浏览器草稿；关闭、刷新或断网后可恢复，必须点击保存才提交服务器。草稿保存失败会提示。
- **备份和迁移**：启动、每小时、批量导入前及正常关闭时完整备份数据库，备份通过完整性检查后落盘；页面可手动备份、导出 JSON 和 CSV，支持导入旧版 HTML / JSON 填写记录。
- **账号体系**：账号密码登录、自助注册、恢复码重置密码、登录后修改密码。密码使用 PBKDF2 加盐哈希，恢复码只存哈希。密码修改或重置后，其他设备的会话失效。
- **账号隔离**：每个账号只可访问自己的项目、任务、回收站、导出和历史记录；浏览器草稿按账号隔离。尚未实现邀请协作者或跨账号共享项目。
- **访问保护**：HttpOnly 会话、持久化登录限速、同源及 CSRF 校验。未登录不能读取或修改业务数据。
- **手机适配**：窄屏导航、可横向滚动的工作清单及看板、可滚动任务详情。

## 本机启动

需要 Python 3.9 或以上：

```bash
python3 -B server.py
```

打开 <http://127.0.0.1:8765>。Mac 也可双击 `开始使用.command`。

初始账号为 **`admin`**。首次启动会随机生成密码，保存在 **`data/首次登录密码.txt`**。如果运行环境设置了 `BOARD_PASSWORD`，则首次初始化使用该密码（至少 12 字符）；后续启动保留数据库中的密码，不受该环境变量覆盖。初始管理员恢复码保存在 **`data/管理员账号与恢复码.txt`**。

从原共享空间密码版本升级时，系统先备份原数据库，然后将原项目、任务、回收站和修改记录归入 `admin` 账号；**登录密码沿用原空间密码**，旧登录状态失效，需要重新登录。旧浏览器草稿仅供管理员继续恢复。初始化文件仅记录初始凭证，用户修改密码或重置恢复码后，以新密码、新恢复码为准。

数据默认保存在 **`data/project.sqlite3`**，完整备份位于 **`data/backups/`**。`data/` 和密码均已排除在 Git 版本管理之外。

## 登录、注册与找回密码

- **登录**：填写账号和密码。账号不区分英文字母大小写。
- **注册**：填写姓名 / 昵称、账号、密码及确认密码。账号为 4 至 32 位字母、数字、点、横线或下划线，以字母或数字开头；密码为 12 至 128 个字符。注册账号拥有自己的项目空间，原海康项目仍归 `admin`。
- **保存恢复码**：注册成功后展示一次密码恢复码，可下载保存。请确认已保存后再前往登录。恢复码可以重置密码，不要分享给他人。
- **忘记密码**：登录页点击“忘记密码”，填写账号、已保存的恢复码和新密码；成功后旧恢复码失效，必须保存系统提供的新恢复码。这个流程不依赖邮件或短信服务。
- **修改密码**：登录后点击右上角头像或左下角“账号设置”，输入当前密码、新密码和确认密码。当前设备保持登录，其他设备需要重新登录；项目数据及原恢复码保留。

恢复码原文不保存在数据库中，注册和重置后仅展示一次。若同时遗失密码和恢复码，需要联系持有服务器访问权限的部署管理员处理，不能仅凭账号名称重置密码。

## 生成项目工作清单

新建项目 → 填写名称和项目内容 → **提取任务并预览** → 勾选所需任务 → 创建项目。

内容示例：

```text
需求阶段：
1. 完成用户访谈，负责人：张三，截止：2026-11-05
2. 输出需求文档，负责人：李四，截止：2026-11-08，交付物：确认后的需求说明书
交付阶段：
3. 联调测试与验收，截止：2026-11-20
```

系统会生成 3 项工作、阶段分布和下一步行动，创建后默认进入 **项目工作清单**。未写明的负责人、日期、验收标准留空供补充；状态初始为未开始，完成率初始为 0。现有项目点击 **生成工作项** 可以继续追加；不会替换已有任务。

生成器使用本地规则提取，没有调用外部大模型，也不会读取腾讯文档的实时变动或猜测相对日期（如“下周五”）。复杂的自由描述建议先按工作事项分行，生成结果提交前可筛选，保存后可逐项编辑。

## 自动生成可视化看板

录入项目并保存工作项后，进入项目的 **可视化看板** 标签，即可查看自动生成的图表；项目总览卡片也提供 **可视化看板** 直达入口。默认进入项目仍展示工作清单。看板链接可以在登录后重新打开，刷新页面也会保留看板视图。

看板直接使用数据库中已保存的工作项，不需要额外填写统计数字，也不会修改原始记录。当前页面新建、修改、归档或恢复工作项后会自动重算；其他页面或设备修改后，点击 **刷新数据** 读取最新内容。浏览器草稿尚未保存时不纳入看板。

| 组件 | 统计与交互 |
| --- | --- |
| 项目交付时间线 | 按计划结束日期排序，标记已完成、进行中、逾期及负责人；左右滚动，点击编辑 |
| 数字与状态卡片 | 工作项总数、已完成数、已完成任务占比、整体进度、计划工时、已完成折算及逾期数 |
| 阶段任务环形图 | 每个阶段的数量和占比，点击阶段筛选 |
| 负责人堆叠柱状图 | 柱高为工作项数量，颜色区分阶段，点击负责人或图例筛选 |
| 排期甘特图 | 显示已填写起止日期的工作项，条内深色部分表示填写的完成百分比，点击编辑 |
| 负责人执行看板 | 各责任人 / 责任组的任务、计划工时、进度及逾期情况 |
| 交付风险与待补信息 | 逾期 / 受阻 / 已登记风险，以及缺少负责人、日期、进度的记录数量 |

顶部的搜索、阶段、负责人、状态和提醒筛选会同时作用于所有图表；看板显示当前筛选项数及全项目项数，并支持 **清除筛选**。点击 **查看工作清单** 可在保留筛选的情况下切换到明细。

回收站工作项不参与图表统计。未指定负责人单列为“待指定负责人”，多人共同署名按一个责任组统计；未补全日期的工作项保留在总数中，并显示待补数量。完成任务占比按完成数量计算，整体进度按“计划工时与项目进度”所述规则计算，两者含义不同。时间线和甘特图展示排期，不自动推断实际开始或完成日期。

图表由应用自带的 SVG 绘制，不依赖外部图表服务，不向第三方发送项目内容。

## 计划工时与项目进度

工作清单直接显示工作内容、主责人与协作人、状态、日期及完成百分比。点击 **编辑记录** 可修改完整记录；填写起止日期时会预览工时和扣除依据。窄屏可左右滚动查看全部字段。

工时口径为 **有效工作日 × 8H**，起止两天均计入。先判断调休补班，再剔除通知中的放假区间和其他周末。例如：

| 排期 | 有效工作日 | 计划工时 |
| --- | --- | --- |
| 2026-10-01 至 2026-10-10 | 3 天，含 10 月 10 日补班 | 24H |
| 2026-02-14 至 2026-02-28 | 6 天，含两天补班 | 48H |
| 2025-12-31 至 2026-01-04 | 2 天，含 1 月 4 日补班 | 16H |

内置日历来源：[2025 年国务院办公厅通知](https://www.gov.cn/zhengce/content/202411/content_6986382.htm)、[2026 年国务院办公厅通知](https://www.gov.cn/zhengce/content/202511/content_7047090.htm)。项目中的 **工作日历** 可查看来源、修订年度放假 / 补班日期或新增年份；修改仅影响当前账号，保存到数据库并保留日历版本记录，相关项目工时随即重算。自定义日历会明确标记。新增年份请按正式通知填写；系统不会自动把未知年份当成普通周一至周五计算。

计划工时代表排期投入，**不是实际报工或考勤**；不会乘以负责人数量，并行任务的工时也会分别累加。多位负责人共同署名时按一个责任组统计，不自动拆分个人工时。

所有工作项均有可计算工时及进度、且总工时大于 0 时，整体进度按计划工时加权。例如 24H 工作完成 50%、8H 工作完成 100%，项目进度为 62.5%。资料未齐时按已填写任务进度平均，并显示覆盖数量及计算口径。已完成折算工时为“计划工时 × 进度”，不代表实际投入。回收站工作项不参与统计。

## 保存、冲突和历史版本

1. 点击工作清单中的“编辑记录”，或状态看板中的任务卡片。
2. 编辑字段，点击“保存到数据库”；成功提示后才完成服务器保存。
3. 如有其他页面已保存，系统展示最新版本并保留当前填写，手动核对合并后再保存。
4. “修改记录”可以查看并恢复某个历史版本。恢复会新增版本，保留此前的修改链。

原 HTML 看板的填写记录可以从海康项目底部的 **恢复 JSON 备份** 入口上传（也兼容旧版 HTML）。恢复按任务编号合并，文件中没有的任务保留；版本不匹配时整批拒绝，不做部分覆盖。导入前会自动生成数据库备份。

JSON 导出包含当前项目的所有任务（含回收站）、计算工时、统计及账号工作日历快照，适合迁移填写内容；CSV 导出也包含有效工作日、计划工时和计算依据。导入时使用目标账号当前的日历重新计算，不自动覆盖目标账号的日历规则。

完整 SQLite 备份还包含所有项目、任务历史版本、账号、会话、自定义工作日历及日历修改记录。JSON 不包含历史版本。旧版 HTML 如果数据只存在旧浏览器本地，需先在旧页面“保存可分享副本”后导入。

## 导入本地文件和文档链接

在项目顶部点击 **导入工作清单**，工作清单与看板视图均可进入。选择来源后点击 **读取并预览**，直接编辑表格中的任务、负责人、状态、日期、进度等内容，勾选需要的工作项，再点击 **保存到项目**。成功后进入工作清单，清除原筛选，图表随已保存记录自动重算；工时由目标账号的工作日历计算，文件内的工时不会直接覆盖计算结果。

- 本地支持 XLSX、CSV、TSV、JSON、DOCX、TXT、Markdown、包含真实表格的 HTML；单文件最大 2MB、每批最多 2000 个工作项。CSV 支持 UTF-8 和 GB18030。暂不支持 XLS、DOC、PDF、图片和扫描件。
- 表格需有表头，例如“编号、阶段、任务名称、工作内容、负责人、状态、开始日期、结束日期、进度”。弹窗可下载 CSV 示例模板。日期使用完整年月日；百分比建议写成 `50%`，小数 `0.5` 按 50% 解释，数字 `50` 也按 50% 解释。无进度数据保留为未填，不自动推断项目完成情况。
- XLSX 读取所有非空工作表，支持字符串、稀疏单元格和 Excel 日期值。公式必须有已计算的缓存结果。不能识别表头的非空工作表会报错，不会静默跳过。阶段列空白时沿用同表前一阶段。其他未映射列会保存在工作内容中并提示核对。
- 默认 **新增工作项**：已存在、重复或不符合规则的原编号会分配新编号，并在预览中提示。选择 **更新相同编号，其余新增** 时按编号匹配；原记录中未提供或为空的字段保留，回收站中的编号需先恢复。同编号多人修改会整批拒绝，请重新读取核对；跨项目备份仅可作为新工作项导入。
- 预览内容会保存在账号和项目隔离的数据库预览记录中，页面修改另有本机草稿；刷新或稍后打开弹窗可恢复。授权字段不进入草稿。读取阶段不修改实际任务；保存阶段整批校验、备份并提交，失败不会部分写入。网络响应丢失时可对同一预览重试保存，不会重复新增任务。JSON 导出只含已保存的任务，全库备份还含导入预览。

链接读取范围与授权要求：

| 来源 | 支持方式 | 需要的信息 |
| --- | --- | --- |
| 腾讯云 COS / 公开下载链接 | 直接读取支持格式的文件；支持有效的临时签名下载地址 | 链接本身具备下载权限 |
| 腾讯文档 | 真实 HTML 表格可直接读；原生动态文档使用官方导出接口，解析 XLSX / DOCX | Access-Token、Client-Id、Open-Id，及文档导出权限 |
| 飞书 / Lark | 公开文件 / HTML 表格；授权读取电子表格、文档、知识库指向的文档 | 有效的 user / tenant access token、应用读取权限和文档访问权限 |
| 钉钉 | 公开文件 / HTML 表格；授权读取电子表格的工作表及完整范围 | Access Token、operatorId；分享链接不能确定工作簿时需 workbookId。普通文档请导出 DOCX |

**公开分享不代表平台提供无需授权的完整内容接口。** 登录页、验证码页或仅返回页面框架的动态分享页不会生成虚假的任务。需要授权时在“内部文档 / 平台授权信息”中填写临时令牌；令牌仅用于当前读取请求，不保存到数据库、本机草稿或日志，读取结束 / 关闭弹窗后清空。不提供第三方账号密码登录或企业 OAuth 自动授权；实际可读范围取决于平台应用权限和文档权限。

只允许受支持平台域名的 HTTPS 公网链接；每次重定向重新校验目的地址，连接固定到已校验的公网 IP，跨域不转发授权头。链接最大读取 4MB；表格最多 10000 个网格行、256 列、250000 个单元格，超限会明确拒绝并要求拆分，不截断导入。导入来源只保留去除查询参数和片段的地址，避免保存签名参数。

第三方授权适配器有模拟接口测试；企业内部链接仍需要使用实际账号令牌完成部署环境的联调验证。源文档后续修改不会自动同步，需重新读取和保存。

## 备份和恢复

手动创建经过完整性检查的全量备份：

```bash
python3 -B server.py backup
python3 -B server.py check
```

备份不自动清理。请定期将 `data/backups/` 复制到另一台机器或有版本历史的存储中，并监控磁盘空间；同一硬盘上的备份无法抵御整块硬盘损坏。页面也可导出项目 JSON 备份。

恢复单项误改优先使用页面历史版本；恢复误删优先使用项目 / 任务回收站。若需要恢复完整数据库：先停止所有应用实例，再备份整个当前 `data/` 目录；把所选完整 `.sqlite3` 备份复制到一个**新的空数据目录**中并命名为 `project.sqlite3`，然后使用新目录启动（保留旧目录以便回退）：

```bash
python3 -B server.py --data-dir /absolute/path/to/restored-data
```

不得在应用运行期间直接替换 SQLite 文件，也不得丢弃运行中的 `-wal` 文件。恢复历史全库备份将回到该备份时点，新版本数据应先另存备份。

## 部署到服务器

GitHub 保存的是代码，网站运行和数据库存储需要服务器。不要使用 GitHub Pages 承载此应用，也不要将数据库、密码或用户填写内容提交到仓库。

Docker Compose：

```bash
cp .env.example .env
docker compose up -d --build
```

容器中的 `/data` 使用持久卷 `board_data`，容器重建和升级会保留数据。**不要运行 `docker compose down -v`，它会删除数据库卷。** 首次随机密码可在服务器执行下列命令查看，妥善保管：

```bash
docker compose exec web cat /data/首次登录密码.txt
```

单实例小团队部署：应用监听本机 8765 端口，前面配置 Nginx / Caddy 的 HTTPS 反向代理，把 `.env` 的 `BOARD_ORIGIN` 设置为实际域名（例如 `https://projects.example.com`，不带结尾斜线），并设置 `BOARD_COOKIE_SECURE=1`。

数据必须使用本地持久磁盘或容器持久卷；不应放在临时文件系统、共享网络盘或每次发布被替换的代码目录中。该版本采用单实例 SQLite，不支持多个容器各自保存独立数据库，也未提供企业级高可用、团队邀请或细分成员权限。

环境变量：

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `BOARD_DATA_DIR` | 项目目录下 `data/` | 数据库和备份存放位置 |
| `BOARD_HOST` | `127.0.0.1` | 监听地址 |
| `PORT` | `8765` | 端口 |
| `BOARD_PASSWORD` | 自动生成 | 仅首次初始化管理员密码使用 |
| `BOARD_ORIGIN` | 当前 HTTP 来源 | HTTPS 部署时填写公开来源 |
| `BOARD_COOKIE_SECURE` | `0` | HTTPS 部署设置为 `1` |
