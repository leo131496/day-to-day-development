# 序 · 项目工作台

轻量的多项目管理页面：从项目内容生成任务，统一维护看板、待办、进度、风险及交付验收。内置海康 × 致趣项目原有的 50 项计划；Python 标准库 + SQLite，无须安装第三方运行依赖。

## 已实现

- **多个项目**：新增、查看、编辑、删除到回收站、恢复，项目数据相互隔离。
- **任务增删改查**：自定义编号、阶段、负责人、协作方、项目内容、排期、状态、完成率、优先级、跟进日期、下一步行动、问题风险、协调决策、验收标准、交付链接和验收结论。
- **自动生成**：粘贴按行或编号整理的项目内容，提取任务、阶段、明确写出的负责人和日期，预览勾选后保存。现有项目可继续追加生成任务。
- **三个关联视图**：状态看板、可搜索筛选的待办清单、项目数据概览（阶段完成率、状态分布、优先关注事项）。新增、修改和删除任务后同步计算。
- **持久保存**：SQLite 数据库事务、WAL、FULL 同步；只有事务提交成功才显示保存成功。服务重启不覆盖已有数据，种子计划仅初始化一次。
- **防误操作**：项目和任务删除均可恢复；任务每次修改、导入、归档和恢复均保留历史版本；并发编辑使用版本检查，不静默覆盖。
- **草稿保护**：填写时保留当前浏览器草稿；关闭、刷新或断网后可恢复，必须点击保存才提交服务器。草稿保存失败会提示。
- **备份和迁移**：启动、每小时、批量导入前及正常关闭时完整备份数据库，备份通过完整性检查后落盘；页面可手动备份、导出 JSON 和 CSV，支持导入旧版 HTML / JSON 填写记录。
- **账号体系**：账号密码登录、自助注册、恢复码重置密码、登录后修改密码。密码使用 PBKDF2 加盐哈希，恢复码只存哈希。密码修改或重置后，其他设备的会话失效。
- **账号隔离**：每个账号只可访问自己的项目、任务、回收站、导出和历史记录；浏览器草稿按账号隔离。尚未实现邀请协作者或跨账号共享项目。
- **访问保护**：HttpOnly 会话、持久化登录限速、同源及 CSRF 校验。未登录不能读取或修改业务数据。
- **手机适配**：窄屏导航、横向看板、可滚动任务详情。

## 本机启动

需要 Python 3.9 或以上：

```bash
python3 -B server.py
```

打开 <http://127.0.0.1:8765>。Mac 也可双击 `开始使用.command`。

初始账号为 **`admin`**。首次启动会随机生成密码，保存在 **`data/首次登录密码.txt`**。如果运行环境设置了 `BOARD_PASSWORD`，则首次初始化使用该密码（至少 12 字符）；后续启动保留数据库中的密码，不受该环境变量覆盖。初始管理员恢复码保存在 **`data/管理员账号与恢复码.txt`**。

从原共享空间密码版本升级时，系统先备份原数据库，然后将原项目、任务、回收站和修改记录归入 `admin` 账号；**登录密码沿用原空间密码**，旧登录状态失效，需要重新登录。旧浏览器草稿仅供管理员继续恢复。初始化文件仅记录初始凭证，用户修改密码或重置恢复码后，以新密码、新恢复码为准。

数据默认保存在 **`data/project.sqlite3`**，完整备份位于 **`data/backups/`**。`data/` 和密码均已排除在 Git 版本管理之外。

## 登录、注册与找回密码

- **登录**：填写账号和密码。账号不区分英文字母大小写。
- **注册**：填写姓名 / 昵称、账号、密码及确认密码。账号为 4 至 32 位字母、数字、点、横线或下划线，以字母或数字开头；密码为 12 至 128 个字符。注册账号拥有自己的项目空间，原海康项目仍归 `admin`。
- **保存恢复码**：注册成功后展示一次密码恢复码，可下载保存。请确认已保存后再前往登录。恢复码可以重置密码，不要分享给他人。
- **忘记密码**：登录页点击“忘记密码”，填写账号、已保存的恢复码和新密码；成功后旧恢复码失效，必须保存系统提供的新恢复码。这个流程不依赖邮件或短信服务。
- **修改密码**：登录后点击右上角头像或左下角“账号设置”，输入当前密码、新密码和确认密码。当前设备保持登录，其他设备需要重新登录；项目数据及原恢复码保留。

恢复码原文不保存在数据库中，注册和重置后仅展示一次。若同时遗失密码和恢复码，需要联系持有服务器访问权限的部署管理员处理，不能仅凭账号名称重置密码。

## 生成项目看板和待办

新建项目 → 填写名称和项目内容 → **提取任务并预览** → 勾选所需任务 → 创建项目。

内容示例：

```text
需求阶段：
1. 完成用户访谈，负责人：张三，截止：2026-11-05
2. 输出需求文档，负责人：李四，截止：2026-11-08，交付物：确认后的需求说明书
交付阶段：
3. 联调测试与验收，截止：2026-11-20
```

系统会生成 3 项任务、阶段分布和下一步待办。未写明的负责人、日期、验收标准留空供补充；状态初始为未开始，完成率初始为 0。现有项目点击 **生成任务** 可以继续追加；不会替换已有任务。

生成器使用本地规则提取，没有调用外部大模型，也不会读取腾讯文档的实时变动或猜测相对日期（如“下周五”）。复杂的自由描述建议先按工作事项分行，生成结果提交前可筛选，保存后可逐项编辑。

## 保存、冲突和历史版本

1. 点击任务卡片或待办中的“填写跟进”。
2. 编辑字段，点击“保存到数据库”；成功提示后才完成服务器保存。
3. 如有其他页面已保存，系统展示最新版本并保留当前填写，手动核对合并后再保存。
4. “修改记录”可以查看并恢复某个历史版本。恢复会新增版本，保留此前的修改链。

原 HTML 看板的填写记录可以从海康项目的 **导入记录** 入口上传。导入按任务编号合并，文件中没有的任务保留；版本不匹配时整批拒绝，不做部分覆盖。导入前会自动生成数据库备份。

JSON 导出包含当前项目的所有任务（含回收站），适合迁移填写内容；完整 SQLite 备份还包含所有项目、历史版本及账户会话。JSON 不包含历史版本。旧版 HTML 如果数据只存在旧浏览器本地，需先在旧页面“保存可分享副本”后导入。

## 备份和恢复

手动创建经过完整性检查的全量备份：

```bash
python3 -B server.py backup
python3 -B server.py check
```

备份不自动清理。请定期将 `data/backups/` 复制到另一台机器或有版本历史的存储中，并监控磁盘空间；同一硬盘上的备份无法抵御整块硬盘损坏。页面也可导出项目 JSON 备份。

恢复单项误改优先使用页面历史版本；恢复误删优先使用项目 / 任务回收站。若需要恢复完整数据库：先停止所有应用实例，再备份整个当前 `data/` 目录；把所选完整 `.sqlite3` 备份复制到一个**新的空数据目录**中并命名为 `project.sqlite3`，然后使用新目录启动（保留旧目录以便回退）：

```bash
python3 -B server.py --data-dir /absolute/path/to/restored-data
```

不得在应用运行期间直接替换 SQLite 文件，也不得丢弃运行中的 `-wal` 文件。恢复历史全库备份将回到该备份时点，新版本数据应先另存备份。

## 部署到服务器

GitHub 保存的是代码，网站运行和数据库存储需要服务器。不要使用 GitHub Pages 承载此应用，也不要将数据库、密码或用户填写内容提交到仓库。

Docker Compose：

```bash
cp .env.example .env
docker compose up -d --build
```

容器中的 `/data` 使用持久卷 `board_data`，容器重建和升级会保留数据。**不要运行 `docker compose down -v`，它会删除数据库卷。** 首次随机密码可在服务器执行下列命令查看，妥善保管：

```bash
docker compose exec web cat /data/首次登录密码.txt
```

单实例小团队部署：应用监听本机 8765 端口，前面配置 Nginx / Caddy 的 HTTPS 反向代理，把 `.env` 的 `BOARD_ORIGIN` 设置为实际域名（例如 `https://projects.example.com`，不带结尾斜线），并设置 `BOARD_COOKIE_SECURE=1`。

数据必须使用本地持久磁盘或容器持久卷；不应放在临时文件系统、共享网络盘或每次发布被替换的代码目录中。该版本采用单实例 SQLite，不支持多个容器各自保存独立数据库，也未提供企业级高可用、团队邀请或细分成员权限。

环境变量：

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `BOARD_DATA_DIR` | 项目目录下 `data/` | 数据库和备份存放位置 |
| `BOARD_HOST` | `127.0.0.1` | 监听地址 |
| `PORT` | `8765` | 端口 |
| `BOARD_PASSWORD` | 自动生成 | 仅首次初始化管理员密码使用 |
| `BOARD_ORIGIN` | 当前 HTTP 来源 | HTTPS 部署时填写公开来源 |
| `BOARD_COOKIE_SECURE` | `0` | HTTPS 部署设置为 `1` |

## 验证

```bash
python3 -B -m unittest discover -s tests -v
```

API 集成测试覆盖：原 50 项计划、内容生成、CRUD、项目和账号隔离、并发冲突、导入原子性、版本恢复、持久保存、备份校验、旧数据库迁移、注册、登录、密码修改、恢复码一次性重置、会话撤销、限速和跨站请求保护。测试使用临时数据库，不触碰正式数据。

浏览器测试需要 Node.js 22+ 及测试环境安装的 Playwright：

```bash
node tests/browser.mjs
```

覆盖真实页面操作、进程重启保存、草稿恢复、多人冲突合并、回收站、导出、断网恢复、注册登录、恢复码下载、密码修改与重置、其他设备退出及手机布局。截图输出到 `test-results/`。如使用外部安装的 Playwright，可通过 `PLAYWRIGHT_PACKAGE` 指向其 `package.json`。
